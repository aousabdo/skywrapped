# Capture sources and their header quirks

skywrapped reads FITS/XISF headers only. Each source below has a header fixture in `tests/fixtures/headers/` and
tests in `tests/test_vendors.py`; the web page lists them from `skywrapped.TESTED_VENDORS`. Rules live in
`src/skywrapped/_fitsnorm/frame.py`. Fixtures for Seestar, Dwarf 3 and N.I.N.A. are synthetic: valid FITS header
blocks that reproduce the keywords, value types and value formats seen in real files of those apps (no real values,
site cards are the 12.3456 / -65.4321 sentinels, device ids are dropped). The Ekos and Dwarf FITS Studio fixtures are
a header block from two public files, passed through `scripts/make_fixture.py`.

Not tested (no real sample): SharpCap and Vaonis Vespera. They stay `generic` and are not in `TESTED_VENDORS`.

## ASIAIR and Celestron Origin
`CREATOR` "ZWO ASIAIR..." / "Origin ...". The Origin writes `DATE-OBS` in local time. AstroWizard stacks carry no
`CREATOR` and stay `generic`; they are recognised as stacks by `NCOMBINE`/`STACKCNT` and the file name.

## N.I.N.A. (`nina`)
- Detection: `SWCREATE` contains `N.I.N.A.` (example `N.I.N.A. 3.2.0.3005 (x64)`).
- `DATE-OBS` is UTC (comment `(UTC)`); `DATE-LOC` is the same instant in local time. We use `DATE-OBS`.
- `IMAGETYP` is `LIGHT`; `EXPOSURE` and `EXPTIME` are both present and equal; `GAIN`, `XPIXSZ`, `FOCALLEN`, `FILTER`
  are ordinary. `SITELAT`/`SITELONG` are written when the profile has a site.

## ZWO Seestar (`seestar`)
- Detection: `CREATOR` contains `Seestar` (example `ZWO Seestar S50`) or `INSTRUME` starts with `Seestar`, or `TELESCOP` is `S30`/`S50`/`S50_<id>`, or the file is named `Stacked_<n>_*` and carries `STACKCNT`/`TOTALEXP`.
  Limitation: a Seestar stack that has none of these clues reads as `generic` and is treated like a desktop stack (dropped whenever its target has any subs).
- `DATE-OBS` is UTC with microseconds (example `2026-05-14T03:12:45.931528`; the file name carries the local time).
- Subs: `IMAGETYP 'Light'`, `EXPTIME`/`EXPOSURE` = sub length, and `TOTALEXP` = the same single sub length (10 for a
  10 s sub), so `TOTALEXP` must not be read as a stack total on its own.
- Stacks (`Stacked_*.fit`): same `IMAGETYP 'Light'`, `NAXIS 3` (colour planes), `STACKCNT` = number of stacked subs,
  `EXPTIME` still the single-sub length, `TOTALEXP` = `STACKCNT` x `EXPTIME` (120 x 10 = 1200). Integration is
  `TOTALEXP` when present, else `STACKCNT` x `EXPTIME`. Stacks also carry a TAN-SIP plate solve (`CTYPE1`, `CD1_1`...).
- `TELESCOP` is `S50_<hex id>` on real files: a device id, reduced to `S50` in the fixtures.
- Stacked files of a target whose subs are also present are skipped by the stats (`stack_with_subs`), never added.

## Dwarf 3 (`dwarf`)
- Detection: `ORIGIN 'DWARFLAB'`, or `INSTRUME` starts with `DWARF` (`DWARFIII` in the app's files, `DWARF 3` in
  files exported by FITS Studio).
- No `IMAGETYP`/`FRAME` keyword: frame type is `unknown`, counted as a light and reported under `type_assumed`.
- Subs have `NAXIS 2` (one Bayer plane, `BAYERPAT 'RGGB'`). Stacks have `NAXIS 3` with `NAXIS3 = 3`, and their file
  name starts `stacked-`; `RESTACK` (comment "is Mega Stack") is 0 in the samples and 1 would also mark a stack.
- A stack's `EXPTIME` is the total integration (2580 s in a stack of 60 s subs); no keyword gives the sub count, so a
  Dwarf stack counts as one frame with its true hours. The `stacked-16` in the file name does not match
  `EXPTIME / 60`, so it is not used.
- `DATE-OBS` comment is "Time end of exposure" and equals the time in the file name, which is the device's own clock;
  the header never says UTC. It is read as local time with the exposure subtracted (start = end - `EXPTIME`).
  This is the one assumption here without a header proof; the night is right in either reading unless the device
  clock was set to UTC.
- No site cards; `CAMERA 'TELE'` names the tele/wide lens, not the sensor.

## Ekos / KStars (`ekos`)
- Detection: INDI drivers write `FRAME` together with `PIXSIZE1` (example `FRAME 'Light'`, `PIXSIZE1 5.2`). The files
  also carry `COMMENT Generated by INDI` and `HISTORY Modified by KStars`, but the header reader skips COMMENT and
  HISTORY cards, so the keyword pair is the rule.
- Type from `FRAME` (`Light`, `Dark`, `Flat`, `Bias`). `DATE-OBS` is UTC (comment "UTC start date of observation").
- Numbers use E notation (`EXPTIME 3.000000E+01`), which the reader parses as floats.
- The fixture is KStars' own simulator test image (`INSTRUME 'CCD Simulator'`), so the mount-like name
  `Telescope Simulator` is dropped from the telescope field.

## Frame types
`IMAGETYP` (then `FRAME`) gives the type: light, dark, flat, bias or dark flat. A value that names none of them
(`SNAPSHOT`, `FOCUS`, `TEST`...) makes the frame `other`: never counted, reported under `skipped["not_light"]`. A
`FRAME` card that names a coordinate system (`FK5`, `ICRS`...) is not a type keyword. Only a frame with no type keyword
at all is `unknown`, and is then typed by its file name or its folders (below).

## Unlabelled frames: calibration folders (R27, R27b)
A frame still `unknown` after IMAGETYP/FRAME and the file-name prefix is typed from its two nearest folders (parent,
grandparent), and only when a folder is clearly calibration: every token of its name (lower-case, split on
non-alphanumerics) is a calibration word (dark(s), flat(s), bias(es), offset(s), darkflat(s), flatdark(s), cali,
calibration, master(s)) or a neutral word (raw, frame(s), dwarf, library, lib, tele, wide) or a number, exposure
(`300s`), temperature (`10c`), `gainN`, `binN` or `isoN`, and at least one token is a calibration word. The type
comes from the calibration word (`cali`/`calibration`/`master` alone give `calibration`, counted under
`skipped["calibration"]`). `Dark_Nebula`, `B33_Horsehead_dark_nebula`, `Dark Sky Camp` and `Dark_Horse` fail the
all-tokens test, so their frames stay `unknown` (counted as lights, flagged `type_assumed`); so does
`Flats/M31/2026-11-10/x.fits` (the calibration word is three levels up). Keywords and the file-name prefix win.
